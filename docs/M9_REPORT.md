## 만든 것

- **core** `signature::remove_white`와 `normalize_with`
  - 종이 밝기는 이미지 밝기의 95번째 백분위로 잡는다.
  - 강도 0~100에 따라 지우는 범위가 넓어지고, 경계는 부드럽게 이어진다.
  - 반투명 가장자리는 종이가 섞인 만큼 색을 되돌린다.
  - 종이가 없는(어두운) 이미지는 바꾸지 않는다.
- **Tauri**
  - `signature_preview`: 긴 변 800px 미리보기
  - `signature_add`: `removeWhite` 인자를 받는다.
  - `signature_add_png`: 그린 서명을 받는다.
- **CLI** `signature` 명령. 개발 서버 `/__signature`가 이 명령으로 브라우저 모드와 E2E에서도 같은 core 처리를 돌린다.
- **대화상자**
  - "이미지로 추가"를 누르면 미리보기 단계를 거친다. 체크무늬 배경, 스위치, 강도 슬라이더, 이름이 있다.
  - "직접 그리기"가 새로 생겼다. 그리기 칸, 잉크 색, 다시 그리기, 이름이 있다.
- **합성 fixture** `tests/fixtures/signatures/sig-white.jpg`: 회색빛 종이, 오른쪽 그늘, 파란 잉크. `npm run fixtures`가 만든다.

## 계획과 달라진 점, 발견한 문제

1. **강도 슬라이더를 처음부터 넣었다.** 계획에서는 사람 확인 뒤 더하려 했다. 사용자 결정으로 바꿨다. 사진 환경이 너무 달라 고정값으로 모든 경우를 테스트할 수 없기 때문이다.
2. **투명 PNG를 지울 뻔했다.** 테스트가 문제를 잡았다. 이미 투명한 배경에 어두운 잉크만 있는 이미지에서는 "종이 밝기"가 잉크 밝기로 잡혀 전부 지워졌다. 종이 밝기가 128 미만이면 지우지 않게 했다. 스위치의 기본값도 투명 이미지에서는 꺼짐이다.
3. **개발 서버 정규식의 역슬래시가 빠졌다.** 스크립트로 편집하다 생긴 실수로, E2E가 잡아 고쳤다.
4. **사진 서명이 미리보기에서 너무 작았다(사람 확인).** 휴대폰 사진은 종이가 대부분이라 서명이 작게 보여 잘 지워졌는지 판단하기 어려웠다. 지운 뒤 잉크 둘레로 자르게 했다(D44). 쪽에 놓을 때 빈 종이만큼 큰 상자가 생기던 문제도 함께 없어졌다. 미리보기 칸을 키우고 "실제 크기로 보기"를 더했다. core 테스트 1개를 새로 넣고 E2E를 보강했다.

## 남은 위험

- **실제 사진의 다양성:** 색 종이, 줄 공책, 강한 그림자, 형광등 반사는 슬라이더로도 깔끔하지 않을 수 있다. 사람 확인 결과에 따라 자르기나 대비 조정 같은 다음 단계를 제안한다.
- **펜 압력:** 펜 압력은 기기와 드라이버에 따라 다르게 들어온다. 압력이 0으로 들어오면 고른 굵기로 그린다.

## 사람 확인 점검표

새 exe(`target\release\HumblePDF.exe`)로 확인한다. 실제 서명 사진은 저장소에 넣지 않는다.

1. **사진 서명:** 흰 종이에 서명하고 휴대폰으로 찍은 사진을 "이미지로 추가"로 고른다.
   - 흰 배경 지우기가 켜진 채 시작하는가
   - 종이와 그림자가 지워지고 글씨는 또렷한가
   - 미리보기가 서명 둘레로 잘려 크게 보이는가. "실제 크기로 보기"로 가장자리를 확인할 수 있는가
   - 슬라이더를 움직이면 미리보기가 바로 바뀌는가. 어느 값이 가장 좋았는가
2. **투명 PNG:** 이미 투명한 서명 PNG를 고르면 스위치가 꺼진 채 시작하는가. 켜도 서명이 사라지지 않는가.
3. **직접 그리기:** 마우스(가능하면 펜이나 터치)로 그린다.
   - 선이 끊기지 않고 부드러운가
   - 검정·파랑 전환과 다시 그리기가 되는가
4. **배치와 저장:** 두 서명을 쪽에 놓고 저장한 뒤 Edge와 Acrobat Reader에서 열어 본다. 배경이 투명하고 위치가 맞는가.
