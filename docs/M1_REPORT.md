## 만든 것

- **화면**
  - 툴바: 파일 추가, 썸네일 패널 토글, 줌 −/+, 배율 표시, 너비 맞춤, 쪽 맞춤, 쪽 번호 입력 / 전체 쪽수
  - 썸네일 패널: 현재 쪽 강조, 누르면 이동, 현재 쪽을 따라 자동 스크롤
  - 연속 스크롤 본문, 빈 문서 안내 화면
  - 비밀번호 대화상자, 오류 알림(sonner)
  - 모든 문자열은 `src/strings/ko.ts`에 있다.
- **파일 추가**
  - 대화상자 또는 창에 끌어다 놓기로 추가한다.
  - 함께 넣은 파일은 이름순으로 정렬한다. 숫자는 숫자로 비교하고, 탐색기처럼 라틴 문자를 한글보다 앞에 둔다.
  - 암호 PDF는 비밀번호를 묻고, 틀리면 같은 대화상자에서 다시 묻는다. 건너뛰면 그 파일만 빠진다.
  - 읽을 수 없는 파일은 알림을 띄우고 나머지 파일을 계속 추가한다.
- **렌더링** (`src/viewer/`)
  - 소스마다 pdf.js 문서나 ImageBitmap을 한 번만 연다.
  - 우선순위 스케줄러: 보이는 쪽 > 주변 ±2쪽 > 썸네일 순이고, 동시에 2개까지 렌더링한다. 화면을 벗어난 작업은 취소한다.
  - 다시 그리는 동안에는 이전 그림을 CSS로 늘려 보여 준다.
  - 캔버스 해상도에 devicePixelRatio를 반영한다.
  - 썸네일은 너비 120px로 그려 캐시한다(키는 페이지와 회전).
- **줌:** 25~400%, 16단계. 너비 맞춤은 가장 넓은 페이지, 쪽 맞춤은 현재 쪽을 기준으로 한다. 배율을 바꿔도 화면 위쪽(Ctrl+휠이면 커서 아래)의 문서 위치가 그대로 남는다.
- **이미지 페이지:** core가 계산한 `imageRect`에 좌표 모듈의 변환으로 그린다. 오버레이가 쓸 변환과 같다.

| long task(50ms 초과) | 0건 | 합성 fixture의 단순한 페이지 기준 |

| 50MB PDF 첫 쪽 표시 (릴리스 exe) | 약 0.70초 (704 / 693 / 708ms) | M0는 약 0.69초 |

## 계획과 달라진 점, 발견한 문제

1. **shadcn CLI 4.23이 넣은 것**
   - 부품이 `@/lib/utils` 대신 npm `cn` 패키지를 가져온다. 확인해 보니 shadcn 팀의 패키지(MIT)라서 그대로 두고, 대신 필요 없어진 `clsx`·`tailwind-merge`를 뺐다.
   - sonner 래퍼가 `next-themes`를 요구해서 빼고 밝은 테마로 고정했다.
   - CSS가 `shadcn/tailwind.css`를 가져와 `shadcn`이 실행 의존성으로 들어갔다. 빌드할 때만 필요하므로 개발 의존성으로 옮겼다(D22).
2. **TypeScript 6에서 `baseUrl`이 폐지 예정이라 오류가 난다.** 경로 별칭은 `paths`만으로 설정했다.
3. **`ko` 로캘 정렬은 한글을 라틴 문자보다 앞에 둔다.** 탐색기 순서에 맞추려고 `en` 로캘(숫자 비교)을 썼다. 한글끼리의 순서는 같다.
4. **현재 쪽 판정:** 마지막 쪽이 짧으면 끝까지 스크롤해도 "화면 위 1/3 지점" 기준으로는 마지막 쪽이 되지 않았다. 끝까지 스크롤하면 마지막 쪽으로 보도록 고쳤다.
5. **비밀번호 재시도 간헐 실패:** 틀렸을 때 대화상자를 닫았다 바로 열면, 닫히는 중인 배경막이 새 대화상자를 덮었다. E2E 반복 실행에서 3번에 1번꼴로 실패했다. 재시도 중에는 대화상자를 열어 둔 채 "확인 중"으로 두도록 고쳤다.
6. **브라우저 모드의 이미지 처리:** 이미지 레이아웃은 core만 계산한다(SPEC 6.1). 그래서 mock 백엔드는 E2E 준비 단계에서 CLI가 계산해 둔 결과(`out/e2e/info/`)를 읽는다. 결과가 없으면 `unsupported`를 낸다.
7. **범위 밖으로 미룬 것** (계획대로)
   - 파일 추가 위치는 문서 끝이다. "선택된 페이지 뒤" 규칙은 선택이 생기는 M2에서 적용한다.
   - 저장하지 않은 변경 확인(Ctrl+N, 창 닫기)은 저장이 생기는 M2에서 다룬다.

## 남은 위험

- **실제 문서의 렌더링 부하:** 위 측정의 한계와 같다. M2 이후 실제 크기의 합성 문서(이미지가 많은 페이지)로 다시 잴 것을 제안한다.
- **썸네일 캐시:** 페이지마다 캔버스를 보관한다. 300쪽이면 약 25MB다. 수천 쪽이면 상한이 필요하다.
- **끌어다 놓기 경로:** Tauri에서는 네이티브 경로로 받고, 브라우저 모드에서는 HTML5 drop으로 받는다. Tauri 쪽은 사람 확인 항목이다.

### 6번 원인과 수정

- **원인 1 (깜빡임):** 배율이 바뀌면 새 레이아웃은 바로 그려지지만, 줌 기준점을 지키는 스크롤 위치는 한 프레임 늦게 반영된다. 그 프레임에 보이는 페이지 범위가 잘못 계산되어, 화면에 있던 페이지가 내려갔다가 빈 캔버스로 다시 올라왔다.
- **원인 2 (답답함):** 다시 올라온 페이지는 새 렌더링이 끝날 때까지 비어 있었다. 휠 한 칸마다 렌더링을 처음부터 다시 시작해 작업이 계속 취소되고 다시 시작되었다.
- **수정**
  - 최근 페이지 그림 캐시(`src/viewer/pageBitmapCache.ts`, 24쪽)를 두었다. 다시 올라온 페이지는 화면에 칠하기 전에 마지막 그림을 CSS로 늘려 바로 보여 준다.
  - 이미 그림이 있는 페이지는 배율이 멈추고 150ms 뒤에 다시 렌더링한다.
- **검증:** `tests/e2e/zoom-smooth.spec.ts`가 Ctrl+휠로 12번 확대·축소하는 동안 매 프레임 화면 안 페이지를 검사한다.

## 사람 확인 점검표

`npm.cmd run tauri dev`로 앱을 연다.

1. **파일 추가:** "파일 추가"로 `tests\fixtures`의 `rotated.pdf`, `mixed_sizes.pdf`, `photo.jpg`, `alpha.png`를 한 번에 고른다. 다음을 확인한다.
   - 이름순(alpha → mixed_sizes → photo → rotated)으로 한 문서가 되고 전체 11쪽인가
   - 이미지가 똑바로 보이는가
2. **끌어다 놓기:** 탐색기에서 PDF 두 개를 창에 끌어다 놓으면 문서 끝에 이어지는가.
3. **암호 PDF:** `encrypted_aes256.pdf`를 추가한다. 비밀번호는 `fixture-pass`다.
   - 틀린 비밀번호를 넣으면 같은 창에서 다시 묻는가
   - 맞으면 열리는가
   - "이 파일 건너뛰기"를 누르면 그 파일만 빠지는가
4. **읽을 수 없는 파일:** `broken.pdf`를 추가하면 오류 알림이 뜨고 앱이 계속 동작하는가.
5. **300쪽 스크롤:** `pages_300.pdf`를 열고 휠과 스크롤바로 빠르게 끝까지 내렸다 올린다.
   - 끊김이 느껴지는가
   - 페이지가 금방 그려지는가
   - 쪽 번호 표시가 따라오는가
6. **줌:** Ctrl+휠, 줌 버튼, 너비 맞춤, 쪽 맞춤.
   - 커서 아래 위치가 유지되는가
   - 고해상도(배율 125% 이상) 화면에서 글자가 선명한가
7. **쪽 이동:** 쪽 번호 칸에 숫자를 넣고 Enter를 누르면 그 쪽으로 가는가. 썸네일을 누르면 이동하는가.
