## 만든 것

- **설치 파일(NSIS):** 사용자별 설치(관리자 권한 없음), 한국어·영어·일본어, WebView2 단계 없음, zlib 압축.
- **연결 프로그램 등록:** 설치 훅이 HKCU에 ProgID, `.pdf\OpenWithProgids`, Capabilities, `RegisteredApplications`를 쓰고, 제거할 때 지운다. 기본 앱은 건드리지 않는다.
- **단일 인스턴스:** `tauri-plugin-single-instance`. 마지막으로 쓴 창에 `open-files` 이벤트로 파일을 넘긴다.
- **새 창:** `open_window` 명령, 창별 시작 파일, `doc-*` 창 권한. 창 상태는 첫 창만 기억한다.
- **질문 대화상자:** "파일 열기 — 지금 문서에 추가 / 새 창에서 열기 / 취소"(세 언어).
- **버전 0.2.0**, 릴리스 워크플로(설치 파일과 해시 추가), README(설치·기본 앱 설정 안내), 점검표, CLAUDE.md 명령.

## 계획과 달라진 점

1. **Tauri의 `fileAssociations`를 쓰지 않았다.** 확인해 보니 그 설정은 `.pdf`의 기본 연결 값을 덮어써서, 사용자가 기본 앱을 고른 적이 없는 PC에서는 HumblePDF가 기본 앱이 된다. 사용자가 고르게 하는 것이 Windows 11의 방식이라 설치 훅으로 "연결 프로그램"에만 등록했다.
2. **압축을 LZMA에서 zlib로 바꿨다.** NSIS의 LZMA 모듈은 CPL-1.0이라 허용 목록(규칙 9) 밖이다. 설치 파일이 1.6MB 커졌다.
3. **"새 창에서 열기"를 위해 여러 창을 지원했다.** 처음 SPEC은 "그 창에 추가"였는데, 사용자 결정으로 묻기로 바꾸면서 필요해졌다.

## 남은 위험

- **설치 파일은 이 PC에서 설치해 보지 않았다.** 레지스트리와 시작 메뉴를 바꾸므로 사람 확인에 맡겼다.
- **CI의 설치 파일 빌드:** 릴리스 워크플로는 태그를 올릴 때 처음 돈다. NSIS를 GitHub에서 받는 단계가 러너에서 실패하면 원인을 보고한다.
- 서명 보관함은 창마다 시작할 때 읽는다. 한 창에서 추가한 서명은 다른 창에서 대화상자를 다시 열 때가 아니라 그 창을 새로 열 때 보인다.
- 제거 화면의 "앱 데이터 삭제"를 고르면 서명 보관함도 지워진다(Tauri 기본 동작, 기본값은 꺼짐).

## 사람 확인 점검표

`target\release\bundle\nsis\HumblePDF_0.2.0_x64-setup.exe`와 `target\release\HumblePDF.exe`로 확인한다.

1. **설치:** 설치 파일을 실행한다.
   - UAC(관리자 권한) 창 없이 설치되는가
   - 시작 메뉴에 HumblePDF가 생기고 실행되는가. 서명 보관함과 설정이 포터블 때와 같은가
2. **연결 프로그램:** PDF 오른쪽 클릭 → 연결 프로그램.
   - HumblePDF가 아이콘과 함께 나오는가. 설정 > 앱 > 기본 앱에도 나오는가
   - 설치만으로 지금의 기본 앱이 바뀌지 않았는가
   - 설치한 HumblePDF를 "항상"으로 골라 더블클릭하면 열리는가
3. **단일 인스턴스:** 앱이 켜진 상태에서 PDF를 더블클릭한다.
   - 빈 창이면 바로 열리는가
   - 문서가 있으면 묻는가. "지금 문서에 추가", "새 창에서 열기", "취소"가 각각 맞게 되는가
   - 새 창은 따로 저장·닫기가 되는가. 닫을 때 그 창의 변경만 묻는가
4. **제거:** 설정 > 앱에서 제거한다.
   - 시작 메뉴와 연결 프로그램 항목이 사라지는가
   - 포터블 exe로 해 둔 연결과 서명 보관함은 남는가("앱 데이터 삭제"를 고르지 않았을 때)
