# 릴리스 점검표

공개 릴리스 전에 사람이 확인하는 항목이다. 자동 테스트(CI)가 통과한 커밋에서 `npm run build:exe`로 만든 `target\release\HumblePDF.exe`로 확인한다. 실제 문서나 서명 대신 `tests\fixtures`의 합성 파일을 쓴다.

결과는 릴리스마다 `docs/M7_REPORT.md`(첫 릴리스) 또는 릴리스 노트에 적는다.

## 1. 시작과 설정

- [ ] exe를 다른 폴더로 옮겨도 실행된다. 인터넷을 끊어도 모든 기능이 동작한다.
- [ ] 처음 실행하면 Windows 표시 언어로 나온다. 툴바에서 English, 日本語로 바꾸면 화면, 창 제목, 저장 기본 이름이 바뀐다.
- [ ] 창 크기와 위치를 바꾸고 닫았다 다시 열면 그대로다. 최대화 상태도 유지된다.
- [ ] 도구 속성(색, 두께, 글자 크기), 썸네일 패널, 줌 방식이 다시 열어도 유지된다.
- [ ] F1로 단축키 도움말이, 툴바의 정보 버튼으로 버전과 라이선스가 나온다.

## 2. 열기와 보기 (M1)

- [ ] PDF 여러 개와 JPG·PNG를 한 번에 추가하면 이름순으로 이어진다. 창에 끌어다 놓아도 된다.
- [ ] PDF의 "연결 프로그램"으로 HumblePDF를 고르거나 기본 앱으로 정한 뒤 더블클릭하면 그 파일이 열린다(경로에 한글·공백 포함).
- [ ] 작업 표시줄, 탐색기, 창 제목 표시줄에 빨간 PDF 아이콘이 보인다.
- [ ] 암호 PDF(`encrypted_aes256.pdf`, 비밀번호 `fixture-pass`)는 비밀번호를 묻고, 틀리면 다시 묻는다.
- [ ] 깨진 파일(`broken.pdf`)은 알림만 띄우고 나머지는 추가된다.
- [ ] `pages_300.pdf`에서 스크롤과 Ctrl+휠 줌이 끊기거나 깜빡이지 않는다.

## 3. 페이지 정리와 저장 (M2)

- [ ] 썸네일 끌기(여러 장 포함, 패널 끝 자동 스크롤, Esc 취소), 회전, 삭제, 이미지 맞춤, 실행 취소·다시 실행
- [ ] 썸네일 오른쪽 클릭 "N쪽 내보내기…"로 고른 쪽만 문서 순서대로 새 PDF가 된다(기본 이름 `<소스>_발췌.pdf`). 그 뒤 Ctrl+S 대상과 저장하지 않은 변경 표시는 그대로다.
- [ ] 다른 이름으로 저장의 기본 이름이 `<첫 쪽 소스>_편집.pdf`다. 두 번째 Ctrl+S는 묻지 않고 덮어쓴다.
- [ ] 열려 있는 원본 PDF로 저장하려 하면 거부된다. 원본은 바뀌지 않는다.
- [ ] 바꾼 뒤 창을 닫으면 저장 / 저장 안 함 / 취소를 묻는다.

## 4. 도형, 하이라이트, 텍스트, 서명 (M3~M5)

- [ ] 하이라이트, 사각형, 타원, 직선, 화살표를 회전된 페이지에서도 그리고, 선택·이동·크기 조절·속성 변경·삭제할 수 있다.
- [ ] 하이라이트 아래 글자가 보인다.
- [ ] 텍스트: 한글·일본어 입력기로 입력, Enter 줄바꿈, Ctrl+Enter 확정, Esc 취소, 더블클릭 다시 편집. 페이지 끝에서도 페이지 안에 남는다.
- [ ] 서명 보관함: PNG·JPG 등록, 이름 변경, 삭제, 다시 열어도 유지. 배치한 서명은 지울 수 없다.
- [ ] 서명 도구는 포인터에 미리보기가 따라오고, 클릭할 때마다 하나씩 놓인다.
- [ ] Ctrl+C / Ctrl+V / Ctrl+D로 객체를 복사·붙여넣기·복제한다(다른 쪽, 회전된 쪽 포함).

## 5. 다시 열기와 평탄화 (M6)

- [ ] 앱으로 저장한 파일을 다시 추가하면 객체가 편집 가능하게 돌아오고 겹쳐 보이지 않는다.
- [ ] 다른 프로그램에서 옮긴 주석은 그림으로 남는다.
- [ ] 평탄화 내보내기 결과에는 주석이 없고, 그 뒤 Ctrl+S는 원래 파일에 저장한다.

## 6. 다른 뷰어

`npm run sample`로 샘플을 만들고, 앱에서 저장한 파일과 함께 Acrobat Reader, Edge, Chrome에서 연다.

- [ ] `out\m0_sample.pdf` ~ `out\m6_flattened.pdf`가 세 뷰어에서 같은 모습이다. 잘리거나 빠진 것이 없다.
- [ ] 주석(하이라이트·도형·텍스트)은 Acrobat Reader와 Edge에서 선택·이동·삭제된다. 서명과 평탄화 결과는 선택되지 않는다.
- [ ] 텍스트를 복사하면 원문(일본어 포함)이 나온다.

## 7. 공개 전

- [ ] KIPRIS(https://www.kipris.or.kr)에서 상표 "HumblePDF", "험블PDF"를 검색해 같은 분류(제9류 소프트웨어 등)의 등록·출원이 없는지 확인했다.
- [ ] `npm run notices`로 `THIRD_PARTY_NOTICES.md`를 다시 만들었고 바뀐 것이 없다(또는 커밋했다).
- [ ] README의 다운로드·SmartScreen 안내가 실제 릴리스와 맞다.

## 릴리스 절차

1. 버전을 올린다: `Cargo.toml`(`[workspace.package] version`), `package.json`, `src-tauri/tauri.conf.json`(있다면)을 같은 값으로 맞춘다. `npm install --package-lock-only`로 잠금 파일을 맞춘다.
2. 위 점검표를 확인하고 결과를 적는다.
3. `git tag v<버전>` 후 `git push origin v<버전>`. GitHub Actions의 Release 워크플로가 exe를 빌드해 **초안** 릴리스를 만든다(`HumblePDF.exe`, `HumblePDF.exe.sha256`, `LICENSE`, `THIRD_PARTY_NOTICES.md`).
4. GitHub의 Releases에서 초안의 설명을 채우고, 내려받은 exe의 해시가 맞는지 확인한 뒤 **Publish**한다.
