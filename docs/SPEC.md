# HumblePDF 기능 명세

초안 v0.1 · 2026-11-13

이 문서는 무엇을 만들지와 완료를 판정하는 기준을 정한다. 결정의 이유는 `DECISIONS.md`에 있다. "M0에서 확인"이라고 적힌 항목은 아직 가정이며, 기술 검증 결과에 따라 고친다.

## 1. 목표

Windows 11에서 설치 없이 실행되는 오프라인 PDF 편집기를 만든다.

1. 여러 PDF와 이미지(JPG, PNG)를 한 문서로 합친다.
2. 페이지 순서를 바꾸고, 삭제하고, 회전한다.
3. 등록해 둔 서명 이미지를 페이지에 배치한다.
4. 텍스트, 하이라이트, 기본 도형을 추가한다.
5. 결과를 새 PDF로 저장한다. Acrobat Reader, Edge, Chrome에서 편집 화면과 같은 모습으로 보인다.

## 2. 비목표

다음은 만들지 않는다.

- 원본 본문(기존 글자, 이미지)의 수정이나 삭제
- OCR, 본문 검색
- 양식 필드의 생성과 편집
- 인증서 기반 전자서명과 서명 검증. 이 앱의 "서명"은 이미지를 배치하는 기능이다
- 암호 설정, 권한 설정
- 용량 최적화
- 인쇄, 클라우드 연동, 계정, 자동 업데이트
- 글자 조합(shaping)이 필요한 문자(아랍어, 인도계 문자 등)의 입력

각 기능의 "후순위" 항목은 나중에 검토할 후보다. 요청 없이 구현하지 않는다.

## 3. 구성

```
프런트엔드 (WebView2)
  UI (React)
  상태 저장소: 문서 모델 + Undo 이력
  뷰어: PDF.js가 소스 페이지를 캔버스에 렌더링
  오버레이: 페이지 위 SVG 레이어에서 객체를 그리고 편집

      ▲ 소스 바이트, 페이지 정보
      ▼ 문서 모델(JSON), 저장 경로

백엔드 (Rust)
  src-tauri: 명령, 파일 I/O, 대화상자, 서명 보관함
  crates/core: 소스 검사, 내보내기, 폰트 서브셋
  crates/cli: core를 명령줄로 실행
```

- 편집 세션의 상태는 프런트엔드 저장소가 가진다. 저장할 때 문서 모델 전체를 코어에 넘긴다.
- 코어는 화면을 그리지 않고, 프런트엔드는 PDF 바이트를 만들지 않는다.
- 프런트엔드는 Tauri 없이 브라우저에서도 실행된다(브라우저 모드). 백엔드 호출은 인터페이스 하나 뒤에 두고 Tauri 구현과 mock 구현을 둔다. mock은 PDF.js로 페이지 정보를 얻는다. 화면 테스트와 화면 확인은 브라우저 모드에서 한다.
- CLI는 문서 모델 JSON을 받아 PDF를 만든다. 내보내기 기능은 GUI 없이 검증한다.

### 백엔드 명령

| 명령 | 입력 | 출력 |
|---|---|---|
| `open_source` | 경로, 비밀번호(선택) | 소스 ID, 종류, 페이지 정보 목록, 되살린 객체 목록(7.7절). 비밀번호가 필요하면 다른 오류와 구분되는 오류로 알린다 |
| `source_bytes` | 소스 ID | 렌더링용 바이트 |
| `export_document` | 문서 모델, 출력 경로, 옵션 | 결과 요약과 경고 목록 |
| `signature_list`, `signature_add`, `signature_rename`, `signature_delete` | | 서명 메타데이터 |
| `signature_bytes` | 서명 ID | PNG 바이트 |

- 파일 선택 대화상자와 파일 끌어다 놓기는 Tauri의 기능을 쓴다.
- 큰 바이너리는 JSON으로 직렬화하지 않고 원시 바이너리 응답으로 보낸다.
- PDF.js에 넘긴 바이트 배열은 워커로 소유권이 넘어가 원본 배열을 다시 쓸 수 없다. 다시 필요하면 `source_bytes`를 또 부른다.

## 4. 데이터 모델

원본 정의는 `crates/core`의 serde 구조체다. 아래는 모양을 보이기 위한 표기다.

```ts
type Document = {
  schemaVersion: 1;
  sources: Source[];
  pages: Page[];                    // 출력 순서
};

type Source = {
  id: string;
  kind: "pdf" | "image";
  path: string;
};

type Page = {
  id: string;
  sourceId: string;
  pageIndex: number;                // PDF 소스의 쪽 번호(0부터). 이미지는 0
  imageFit: "a4" | "image" | null;  // 이미지 페이지만 값이 있다
  box: Rect;                        // 보이는 영역 (5장)
  baseRotation: 0 | 90 | 180 | 270; // 원본의 회전. 이미지는 0
  userRotation: 0 | 90 | 180 | 270; // 사용자가 더한 회전
  objects: PageObject[];            // 그리는 순서. 뒤에 있는 것이 위
};

type PageObject = Highlight | Shape | Line | Text | Signature;

type Highlight = { id: string; type: "highlight"; quads: Quad[]; color: Rgb; opacity: number };
type Shape     = { id: string; type: "rect" | "ellipse"; rect: Rect;
                   stroke: Rgb | null; strokeWidth: number; fill: Rgb | null; opacity: number };
type Line      = { id: string; type: "line"; from: Point; to: Point;
                   stroke: Rgb; strokeWidth: number; arrow: boolean; opacity: number };
type Text      = { id: string; type: "text"; origin: Point; rotation: 0 | 90 | 180 | 270;
                   fontSize: number; color: Rgb; lines: string[] };
type Signature = { id: string; type: "signature"; signatureId: string; rect: Rect;
                   rotation: 0 | 90 | 180 | 270 };
```

- `Point`는 `{x, y}`, `Rect`는 `{x0, y0, x1, y1}`(x0 < x1, y0 < y1), `Quad`는 점 4개, `Rgb`는 0~1 범위의 세 값이다. 단위와 방향은 5장을 따른다.
- `Text.origin`은 첫 줄 기준선의 시작점이다. `Signature.rect`는 회전을 적용한 뒤의 경계 상자다.
- `box`와 `baseRotation`은 `open_source`가 준 값을 그대로 넣는다. 코어는 저장할 때 소스에서 다시 계산한 값과 다르면 오류를 낸다.
- 한 원본 페이지는 문서에 한 번만 나온다(페이지 복제는 후순위).
- 비밀번호는 모델에 넣지 않고 세션 메모리에만 둔다.
- 모델은 JSON으로 직렬화되며 CLI의 입력 형식이기도 하다. CLI는 서명 폴더 경로를 따로 받는다.

## 5. 좌표

- **저장 좌표계.** 각 페이지의 PDF 사용자 공간을 그대로 쓴다. 단위는 pt(1/72인치)이고 원점과 방향은 원본 PDF와 같다(y축이 위로 간다). 이미지 페이지는 `[0, 0, 폭, 높이]` 상자를 사용자 공간으로 삼는다.
- **보이는 영역(`box`).** PDF 페이지는 CropBox와 MediaBox의 교집합이다(CropBox가 없으면 MediaBox). PDF.js의 `page.view`와 같은 값이어야 하며, 코어가 계산한 값과 일치하는지 테스트한다.
- **표시 회전.** `(baseRotation + userRotation) % 360`이며 시계 방향이다.
- **화면 변환.** 프런트엔드의 좌표 모듈 하나가 "사용자 공간 ↔ 화면 픽셀" 변환을 맡는다. PDF 페이지는 표시 회전을 넘겨 만든 PDF.js 뷰포트의 변환을 그대로 쓰고, 이미지 페이지는 같은 식의 변환을 직접 만든다. 다른 코드에서 좌표를 직접 계산하지 않는다.
- **객체의 `rotation`.** 텍스트와 서명에만 있다. 사용자 공간에서 반시계 방향으로 돈 각도다. 0이면 글자는 +x 방향으로 진행하고 글자의 위쪽은 +y 방향이다. 객체를 만들 때 그 페이지의 표시 회전 값을 넣으면 화면에서 똑바로 보인다. 이후에 페이지를 회전하면 객체도 페이지와 함께 돈다.
- **코어.** 모델의 좌표를 변환 없이 PDF에 쓴다.
- UserUnit이 1이 아닌 페이지는 지원하지 않는다. 열 때 알린다.

## 6. 기능

### 6.1 문서와 파일 추가 (병합)

- 앱은 문서 하나를 다룬다. 시작 상태는 빈 문서다.
- 파일 추가는 대화상자 또는 창에 끌어다 놓기로 한다. 여러 파일을 한 번에 넣으면 이름순으로 들어가고, 순서는 썸네일에서 바꾼다. 삽입 위치는 선택된 페이지 뒤이며, 선택이 없으면 문서 끝이다.
- 지원 형식은 PDF, JPG/JPEG, PNG다. 확장자가 아니라 파일 내용으로 판별한다.
- PDF를 추가하면 그 PDF의 모든 페이지가 들어간다.
- 이미지 한 장은 한 페이지가 된다. 맞춤 방식은 두 가지이고 페이지별로 바꿀 수 있다.
  - `a4`(기본): A4 용지(595.276 × 841.89pt). 이미지의 가로세로 비에 따라 세로·가로를 자동으로 고르고, 여백 없이 비율을 유지해 가운데에 놓는다.
  - `image`: 페이지 비율을 이미지와 같게 하고 긴 변을 841.89pt로 둔다.
- 두 맞춤 방식의 페이지 상자와 이미지 위치는 코어가 계산해 `open_source` 결과로 준다. 프런트엔드에 같은 계산을 따로 두지 않는다.
- 사진의 EXIF 방향을 반영해 똑바로 보이게 한다.
- 암호가 걸린 PDF는 비밀번호를 묻는다. 틀리면 다시 묻는다. 출력에는 암호를 걸지 않으며 이를 사용자에게 알린다.
- 새 문서(Ctrl+N)와 창 닫기는 저장하지 않은 변경이 있으면 확인을 받는다.
- 후순위: BMP·TIFF·WebP·HEIC, PDF의 일부 쪽만 추가, 이미지 여백 설정, 큰 사진 축소.

### 6.2 뷰어

- 세로 연속 스크롤. 왼쪽에 썸네일 패널을 둔다.
- 줌 25~400%, 너비 맞춤, 쪽 맞춤, Ctrl+휠. 현재 쪽 번호와 전체 쪽수를 보여 주고 쪽 번호를 입력해 이동한다.
- 보이는 페이지와 그 주변만 렌더링한다. 화면 밖으로 나간 렌더링 작업은 취소한다. 썸네일은 낮은 배율로 그려 캐시한다.
- 고해상도 화면에서 선명하게 보인다(devicePixelRatio 반영).
- PDF.js의 워커, cMap, 표준 폰트, wasm, ICC 프로필(`iccs/`) 자산을 앱에 넣고 로컬 경로로 지정한다(DECISIONS D18). 한글 PDF(폰트를 포함하지 않은 PDF 포함)가 깨지지 않아야 한다.
- 후순위: 본문 텍스트 선택과 복사, 검색, 두 쪽 보기, 다크 모드.

### 6.3 페이지 정리

- 썸네일을 끌어 순서를 바꾼다. 여러 장을 선택(Ctrl·Shift 클릭, Ctrl+A)해 한꺼번에 옮길 수 있다. 끄는 동안 Esc를 누르면 취소된다.
- 삭제(Delete), 왼쪽·오른쪽 90° 회전(Ctrl+[, Ctrl+]). 대상은 선택한 페이지이고, 선택이 없으면 현재 쪽이다.
- 이미지 페이지의 맞춤 방식(6.1)은 툴바와 썸네일의 오른쪽 클릭 메뉴에서 바꾼다.
- 파일 추가(6.1)를 포함해 모두 Undo/Redo 대상이다. 선택과 줌은 이력에 넣지 않는다.
- 썸네일 정렬은 포인터 이벤트 기반으로 구현한다. HTML5 드래그 API는 Tauri의 파일 끌어다 놓기 처리와 충돌할 수 있다(M0에서 확인).
- 후순위: 페이지 복제, 빈 페이지 삽입, 선택한 쪽만 내보내기.

### 6.4 객체 공통 조작

- 도구: 선택(V), 텍스트(T), 하이라이트(H), 사각형(R), 타원(O), 직선(L), 화살표(A), 서명(S). 도구와 속성은 툴바 아래 둘째 줄 편집 막대에 있다(DECISIONS D29).
- Esc: 끄는 중이면 취소한다. 그리기 도구에서는 선택 도구로 돌아가고, 선택 도구에서는 객체 선택을 푼다.
- 만들기: 페이지 위에서 끌거나 클릭한다. 객체는 만든 페이지에 속하고 페이지 밖으로 나가지 않는다.
  - 4px 미만으로 움직이면 클릭이다. 클릭하면 사각형·타원은 그 점을 중심으로 화면 기준 가로 120pt, 세로 80pt로, 직선·화살표는 그 점에서 화면 오른쪽으로 120pt로 만든다. 하이라이트는 클릭으로 만들지 않는다.
  - 만든 뒤: 하이라이트 도구는 그대로 남는다. 다른 도구는 선택 도구로 돌아가고 만든 객체가 선택된다.
- 선택: 클릭으로 하나를 선택한다(겹치면 위에 있는 것). 선택하면 조절 핸들이 보인다. 빈 곳을 클릭하면 선택이 풀린다.
- 이동(끌기, 방향키 1pt, Shift+방향키 10pt; 방향은 화면 기준), 크기 조절(핸들. 최소 4pt), 삭제(Delete. 선택한 객체가 있으면 객체를, 없으면 페이지를 지운다), 속성 변경(편집 막대).
- Undo/Redo(Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z). 끌기 한 번은 이력 한 칸이다. 이력은 100칸까지 둔다.
- 최근에 쓴 색, 두께, 글자 크기를 도구별로 기억한다.
- 복사·붙여넣기(DECISIONS D35): Ctrl+C로 선택한 객체를 복사하고 Ctrl+V로 붙여 넣는다. Ctrl+D는 바로 복제한다. 같은 페이지에서는 붙일 때마다 화면 기준 오른쪽 아래로 10pt씩 비켜 놓고, 다른 페이지(선택한 객체의 페이지, 없으면 현재 쪽)에서는 페이지 상자 기준 같은 자리에 놓는다. 텍스트와 서명은 페이지 회전 차이만큼 돌려 화면에서 같은 방향으로 보이게 한다. 페이지 밖으로 나가지 않는다. 붙여 넣은 객체가 선택되고, 한 번이 Undo 한 칸이다. 앱 안에서만 복사하고 시스템 클립보드는 쓰지 않는다.
- 후순위: 다중 선택, 정렬 가이드, 앞뒤 순서 변경, 자유 회전.

### 6.5 하이라이트

- 영역을 끌어 사각형 하이라이트를 만든다. 색 4종(노랑, 초록, 분홍, 하늘), 불투명도 기본 0.4.
- 아래 글자가 가려지지 않아야 한다(곱하기 블렌드).
- 후순위: 본문 글자에 맞춰 붙는 하이라이트, 자유곡선 형광펜, 밑줄·취소선.

### 6.6 도형

- 사각형, 타원: 선 색, 선 두께(0.5~12pt), 채움 색(없음 가능), 불투명도. 선과 채움이 둘 다 없을 수는 없다.
- 색은 고정 팔레트 8색(검정, 빨강, 주황, 노랑, 초록, 파랑, 보라, 흰색), 두께는 0.5·1·2·3·4·6·8·12pt, 불투명도는 10~100%(10% 단위)에서 고른다. 기본값은 빨강, 2pt, 채움 없음, 100%다.
- 직선, 화살표: 선 색, 두께, 불투명도. Shift를 누르고 끌면 45° 단위로 고정된다.
- 화살촉은 끝점에 놓는 닫힌 삼각형이다. 길이는 `max(8, 4 × 선 두께)`pt, 밑변 폭은 길이의 0.6배다. 선은 화살촉 밑변까지만 그린다. 프런트엔드와 코어가 이 수치를 똑같이 쓴다.
- 후순위: 다각형, 둥근 모서리, 점선, 자유곡선.

### 6.7 텍스트

- 텍스트 도구(T)로 클릭한 자리에 입력 상자가 생긴다. 클릭한 점이 첫 줄의 위쪽이다(기준선은 어센트만큼 아래). 한글·일본어 조합이 정상 동작해야 한다(브라우저 입력 상자를 쓴다). Enter는 줄바꿈, 바깥 클릭이나 Ctrl+Enter는 확정, Esc는 취소다. 조합 중의 키는 입력기에 맡긴다. 선택 도구에서 더블클릭하면 다시 편집한다.
- 확정 한 번이 Undo 한 칸이다. 빈 글자는 만들지 않고, 다시 편집해 모두 지우면 객체를 지운다. 확정하면 선택 도구로 돌아가고 그 텍스트가 선택된다.
- 속성은 글자 크기 6~72pt(기본 12, 6·8·9·10·11·12·14·16·18·20·24·28·32·36·48·60·72에서 고른다)와 색(8색 팔레트, 기본 검정)이다.
- 폰트는 번들 폰트 두 종이다(DECISIONS D32): Pretendard와 일본어용 Pretendard JP(자주 쓰는 글자 서브셋). 글자마다 Pretendard에 있으면 Pretendard, 없으면 Pretendard JP를 쓴다. 화면은 CSS 글꼴 대체로 같은 규칙을 따른다.
- 자동 줄바꿈은 없다. 줄은 사용자가 Enter로 나눈다. 줄 간격은 글자 크기의 1.3배이고, 둘째 줄부터는 글자 기준 아래 방향으로 그만큼씩 내려간다.
- 화면과 출력이 일치하도록 화면에서도 번들 폰트를 쓰고 커닝과 합자를 끈다. 글자 폭은 폰트의 기본 전진 폭만 쓴다.
- 크기 조절 핸들은 없다. 크기는 글자 크기로 바꾼다.
- 폰트에 없는 글자가 있으면 저장할 때 어떤 글자인지 알려 준다.
- 후순위: 폰트 선택, 굵게, 정렬, 자동 줄바꿈 상자, 오늘 날짜와 체크 표시 빠른 삽입.

### 6.8 서명

- 보관함: PNG·JPG 파일을 이름과 함께 등록한다. 여러 개를 등록할 수 있다. 목록에 미리보기와 이름이 보이고, 이름 변경과 삭제가 된다. 앱을 다시 켜도 남아 있다.
- 저장 위치는 앱 데이터 폴더(`%APPDATA%` 아래)의 `signatures/`다. 등록할 때 PNG로 정규화하고 긴 변이 2000px를 넘으면 줄인다.
- 배치: 서명 도구(S)에서 편집 막대의 서명을 고르고 페이지를 클릭하면, 화면에 보이는 페이지 폭의 25% 크기로 클릭한 점을 중심으로 놓인다. `rotation`은 페이지의 표시 회전이라 화면에서 똑바로 보인다. 페이지 밖으로 나가지 않는다. 서명 도구에서는 고른 서명이 놓일 크기와 위치 그대로 마우스 포인터를 따라 반투명하게 보인다. 놓은 뒤에도 서명 도구가 남아 클릭할 때마다 하나씩 놓인다(Esc나 V로 선택 도구).
- 편집: 모서리 핸들 4개로 비율을 유지한 채 크기를 바꾼다(마주 보는 모서리 고정). 옮기기, 방향키, 삭제, Undo는 다른 객체와 같다.
- 보관함이 비어 있을 때 서명 도구를 고르면 보관함 대화상자가 열린다. 지금 문서에 배치된 서명은 보관함에서 지울 수 없다(그 쪽 번호를 알린다). 지운 서명이 실행 취소로 되살아나 저장하면 "서명 이미지를 찾을 수 없음" 오류를 알린다.
- 투명 배경을 유지한다.
- 후순위: 흰 배경 자동 투명화, 여러 쪽 일괄 배치, 마우스·펜으로 그리기.

### 6.9 저장

- 다른 이름으로 저장(Ctrl+Shift+S): 기본 파일 이름은 `<첫 쪽의 소스 이름>_편집.pdf`이고(접미사는 UI 언어를 따른다, 6.10), 기본 위치는 그 소스가 있는 폴더다. 한 번 저장한 뒤의 Ctrl+S는 그 파일에 덮어쓴다. 저장한 적이 없으면 Ctrl+S는 다른 이름으로 저장과 같다.
- 현재 열려 있는 소스 파일과 같은 경로로는 저장할 수 없다. 다른 이름을 요구한다.
- 기본 저장: 하이라이트·도형·텍스트는 주석으로, 서명은 페이지에 구워서 저장한다.
- 평탄화하여 내보내기(툴바 버튼, DECISIONS D37): 이 앱에서 추가한 객체를 모두 페이지에 굽는다. 원본에 있던 주석과 양식은 건드리지 않는다. 기본 파일 이름의 접미사는 `_평탄화`(UI 언어를 따른다)다. 결과는 다시 편집할 수 없으므로 저장으로 치지 않는다: Ctrl+S 대상과 "저장하지 않은 변경" 상태를 바꾸지 않는다.
- 저장 중에는 진행 표시를 하고, 실패하면 이유를 보여 준다. 실패해도 기존 파일은 손상되지 않는다.
- 후순위: 원본에 바로 저장, 자동 저장, 원본의 주석과 양식까지 평탄화.

### 6.10 UI 언어

- 한국어, 영어(미국식), 일본어를 지원한다(DECISIONS D27).
- 처음에는 시스템 언어를 따른다. 셋 중 어느 것도 아니면 영어다.
- 툴바의 언어 선택으로 바꿀 수 있고, 고른 언어는 다음 실행에도 유지된다. 바꿔도 문서와 Undo 이력은 그대로다.
- 창 제목, 저장 기본 이름의 접미사(`_편집`, `_edited`, `_編集`), 오류 메시지도 언어를 따른다.
- 출력 PDF의 내용은 언어와 관계없다.
- 텍스트 객체의 글자는 번들 폰트 두 종을 따른다(6.7, D32). 일본어는 JIS X 0208의 글자(가나, 기호, 제1·제2수준 한자)를 지원한다. 그 밖의 드문 한자와 반각 가타카나는 원본 폰트에 없어 저장할 때 빈칸으로 알린다.

## 7. PDF 출력 규칙

코어(`crates/core`)가 지킨다.

### 7.1 문서 조립

- 페이지 목록에서 처음 나오는 PDF 소스의 문서를 기준 문서로 삼아 출력을 만든다. 기준 문서의 카탈로그(북마크, 양식, 메타데이터)는 유지한다. PDF 소스가 없으면 빈 문서에서 시작한다.
- 다른 소스의 페이지는 필요한 객체를 번호가 겹치지 않게 복사해 붙인다.
- 페이지를 옮기기 전에 상속 속성(Resources, MediaBox, CropBox, Rotate)을 각 페이지에 직접 써 넣는다.
- 페이지 트리는 모델의 순서대로 다시 만든다. 출력에 없는 페이지와 그 페이지에서만 쓰던 객체는 제거한다.
- 각 페이지의 `/Rotate`는 `(baseRotation + userRotation) % 360`이다.
- 원본 페이지에 있던 주석(링크, 다른 프로그램의 주석, 양식 위젯)은 그대로 둔다. 7.7절에서 객체로 되살린 주석만 뺀다.
- 여러 페이지가 공유하는 Resources 사전을 고칠 때는 복사한 뒤 고친다.
- 암호화된 소스는 복호화해 쓰고 출력에는 암호를 걸지 않는다.
- `/Producer`에는 앱 이름과 버전(`HumblePDF <버전>`)을 쓴다. 작성자나 사용자 이름은 쓰지 않는다.

### 7.2 이미지 페이지

- JPEG는 다시 인코딩하지 않고 그대로 넣는다(DCTDecode). CMYK JPEG는 RGB로 변환해 넣는다.
- PNG는 8비트 RGB로 풀어 넣고, 투명도는 소프트 마스크(SMask)로 넣는다.
- EXIF 방향은 변환 행렬로 반영한다. 화질이 떨어지는 재인코딩은 하지 않는다.
- 같은 이미지는 출력에 한 번만 넣고 여러 곳에서 참조한다.

### 7.3 모양 XObject

- 모든 객체는 "모양" Form XObject 하나로 만든다. 내용은 페이지 사용자 공간 좌표로 그리고, `/BBox`는 그 객체가 차지하는 영역, `/Matrix`는 항등으로 둔다.
- 주석으로 저장할 때는 이 XObject가 주석의 표시 모양(`/AP /N`)이 된다. 구울 때는 페이지 콘텐츠에서 같은 XObject를 그린다. 그리는 코드는 하나만 둔다.
- 선 두께의 절반만큼 `/BBox`를 넓혀 선이 잘리지 않게 한다.
- 불투명도와 블렌드 모드는 ExtGState로 지정한다.

### 7.4 주석으로 저장

| 객체 | 주석 종류 | 주요 항목 |
|---|---|---|
| 하이라이트 | `/Highlight` | `/QuadPoints`, `/C`, `/CA`. 모양은 곱하기 블렌드 |
| 사각형 | `/Square` | `/C`(선), `/IC`(채움), `/BS`(두께), `/CA` |
| 타원 | `/Circle` | 사각형과 같음 |
| 직선, 화살표 | `/Line` | `/L`, `/LE`(화살표는 끝점 `/ClosedArrow`), `/C`, `/IC`, `/BS`, `/CA` |
| 텍스트 | `/FreeText` | `/Contents`(줄바꿈을 포함한 원문), `/DA`, 테두리 없음 |

- 공통 항목: `/Rect`(모양의 BBox와 같음), `/AP /N`, `/F 4`(인쇄 허용), `/NM`(고유 ID), `/M`(수정 시각). 그리고 이 앱이 만든 주석임을 나타내는 전용 키 하나에 객체 JSON을 넣는다(7.7절).
- `/QuadPoints`의 점 순서는 명세의 문구와 실제 뷰어의 관행이 다르다. Acrobat의 관행(왼쪽 위, 오른쪽 위, 왼쪽 아래, 오른쪽 아래)을 따르고 뷰어 세 종에서 확인한다(M0에서 확인).
- 하이라이트 모양에는 투명 그룹을 지정하지 않는다. 지정하면 곱하기 블렌드가 페이지와 섞이지 않아 글자를 가릴 수 있다(M0에서 확인).
- `/T`(작성자)는 쓰지 않는다.

### 7.5 굽기

- 서명은 항상 굽는다. 평탄화 내보내기에서는 모든 객체를 굽는다.
- 페이지의 기존 콘텐츠 앞뒤를 `q`와 `Q`로 감싸고, 그 뒤에 모양 XObject를 그리는 콘텐츠를 덧붙인다. 감싸지 않으면 원본이 남긴 그래픽 상태 때문에 위치가 어긋난다.
- 리소스 이름에는 원본과 겹치지 않는 접두어를 붙인다.
- 서명 이미지는 RGB와 소프트 마스크로 넣는다.

### 7.6 폰트

- 번들 폰트 두 종(TrueType 윤곽)에서 문서에 쓰인 글자만 남긴 서브셋을 폰트마다 한 번만 넣고, 모든 텍스트 객체가 공유한다. 쓰이지 않은 폰트는 넣지 않는다. 한 줄은 같은 폰트끼리 묶은 조각으로 나눠 조각마다 폰트를 바꿔 그린다.
- Type0 폰트(Identity-H)와 CIDFontType2, 글자 폭 배열(`/W`), ToUnicode CMap을 넣는다. ToUnicode가 있어야 다른 뷰어에서 글자를 복사하고 검색할 수 있다.
- 폰트는 `subsetter`로 서브셋을 만들고 `ttf-parser`로 글자 폭과 매핑을 읽어 core가 직접 구성한다. lopdf의 `font_embedding` 기능은 한글 서브셋을 지원하지 않는다(M0에서 확인, DECISIONS D16). 서브셋이 새로 매긴 글리프 번호를 CID로 쓴다(`/CIDToGIDMap /Identity`).
- 글자 배치에는 글자별 기본 전진 폭만 쓴다. 커닝, 합자, 글자 조합은 하지 않는다.
- 폰트에 없는 글자는 빈 글리프로 쓰고 경고 목록에 담아 돌려준다.

### 7.7 다시 열기

- 이 앱이 만든 주석에는 전용 키에 객체 JSON이 들어 있다. `open_source`는 이런 주석을 찾아 객체로 되살려 돌려주고, 렌더링용 바이트에서는 그 주석을 뺀다. 빼지 않으면 화면에 두 번 그려진다.
- 판정(DECISIONS D36): JSON으로 객체를 다시 그린 상자가 주석의 `/Rect`와 0.01pt 안에서 같으면 되살린다. 다르면 다른 프로그램이 고친 것으로 보고 되살리지 않는다. 그 주석은 원본 주석으로 남는다. 열 때, 렌더링용 바이트를 만들 때, 저장할 때 모두 같은 판정을 쓴다.
- 되살린 객체는 앱이 문서에 넣을 때 새 ID를 받는다. 추가하면 되살린 객체 수를 알린다.
- 렌더링용 바이트는 되살린 주석만 뺀 PDF다(암호는 풀린다). 되살린 주석이 없으면 파일을 그대로 쓴다.
- 저장할 때 되살릴 수 있는 주석은 모든 소스 페이지에서 빼고 현재 객체로 다시 쓴다. 그래서 앱에서 지운 객체는 사라지고 겹치지 않는다.
- 구운 객체(서명, 평탄화 결과)는 되살리지 않는다.

### 7.8 파일 쓰기

- 같은 폴더의 임시 파일에 쓴 뒤 이름을 바꾼다. 실패하면 임시 파일을 지운다.
- 쓰기 전에 출력 경로가 소스 경로와 같은지 확인하고, 같으면 거부한다.

## 8. 오류 처리와 알려진 한계

- lopdf가 읽지 못하는 PDF는 추가할 때 알리고 문서에 넣지 않는다. PDF.js로는 보이더라도 저장할 수 없기 때문이다. 이런 파일이 자주 나오면 DECISIONS의 D4 대안을 검토한다.
- 기준 문서가 아닌 소스의 북마크, 양식 동작, 문서 내부 링크는 보존을 보장하지 않는다.
- 전자서명(인증서)이 들어 있는 PDF를 고치면 그 서명은 무효가 된다. 경고는 후순위로 추가한다.
- 권한 제한이 걸린 PDF는 열 때 제한이 있다는 사실을 알린다.
- 오류 메시지는 UI 언어(6.10)로 쓰고, 무엇이 실패했는지와 사용자가 할 수 있는 일을 적는다. 내부 정보는 로그에만 남긴다.
- 패닉으로 앱이 죽지 않게 한다. core의 공개 함수는 오류를 `Result`로 돌려준다.

## 9. 테스트

- **코어 테스트**(`cargo test`). 모델 JSON으로 내보낸 PDF를 다시 파싱해 쪽수, 순서, 회전, 상자, 주석 항목, 폰트 포함 여부, 파일 크기 한도를 확인한다. 원본 파일이 바뀌지 않았는지 해시로 확인한다.
- **프런트엔드 단위 테스트.** 좌표 변환(회전 4종 × CropBox 오프셋), 모델 변경과 Undo/Redo.
- **화면 일치 테스트**(E2E). 브라우저 모드에서 (가) 모델을 오버레이로 그린 화면과 (나) CLI로 내보낸 PDF를 같은 뷰어로 렌더링한 화면을 비교한다. 객체 경계의 차이가 100% 배율에서 1px 이하여야 한다.
- **사람 확인.** 마일스톤마다 `out/`의 샘플을 Acrobat Reader, Edge, Chrome에서 열어 점검표대로 확인한다. 자동화할 수 없는 항목(주석으로 인식되는지, 글자 복사가 되는지)을 여기서 본다.
- **fixture.** 스크립트로 합성해 만든다. 합성이 어려운 것은 라이선스가 분명한 공개 파일만 쓰고 출처를 적는다. 최소 구성은 다음과 같다.
  - 페이지 구조: 회전 90/180/270 페이지, CropBox가 MediaBox와 다른 페이지, 크기가 다른 페이지가 섞인 문서, 상속 속성을 쓰는 페이지 트리, Resources를 공유하는 페이지들, 콘텐츠가 배열인 페이지
  - 문서 종류: 암호 PDF, 링크·주석·양식 위젯이 있는 페이지, 한글 본문(폰트 포함과 미포함), 300쪽 문서
  - 이미지: 알파 PNG, 16비트 PNG, 팔레트 PNG, 회색조 JPEG, CMYK JPEG, EXIF 회전 JPEG, 8000px 이미지
  - 경로: 한글과 공백이 들어간 경로

## 10. 마일스톤과 수용 기준

한 번에 한 마일스톤만 진행한다. 끝나면 `docs/M<번호>_REPORT.md`에 결과를 적고 멈춘다.

### M0. 기술 검증

스택의 위험한 가정을 기능 개발 전에 확인한다. UI는 검증에 필요한 최소한만 만든다.

| 번호 | 확인할 것 | 통과 기준 |
|---|---|---|
| M0-1 | 골격 | Tauri 2 + React + TypeScript + Vite 앱이 실행된다. Cargo 워크스페이스에 core와 cli가 있다. 설치 프로그램 없이 실행되는 exe가 빌드되고, 다른 폴더로 옮겨도 실행된다. exe 크기를 기록한다. |
| M0-2 | 뷰어 | 한글 PDF fixture(폰트 포함, 미포함)가 PDF.js로 바르게 보인다. 워커·cMap·표준 폰트·wasm이 앱에 들어 있고 실행 중 네트워크 요청이 없다. 50MB PDF를 코어에서 넘겨받아 첫 쪽이 뜨기까지의 시간을 기록한다. 파일을 창에 끌어다 놓으면 경로를 받는다. |
| M0-3 | 병합 | CLI로 PDF 2개와 JPG, PNG를 합친 PDF가 나온다. 재파싱 테스트가 통과하고, 9장의 페이지 구조 fixture와 암호 PDF를 모두 처리한다. 코어가 계산한 페이지 상자가 PDF.js의 값과 일치한다. |
| M0-4 | 주석과 굽기 | CLI로 한글 텍스트, 하이라이트, 사각형, 화살표 주석과 구운 서명 PNG가 들어간 `out/m0_sample.pdf`를 만든다. 한글 20자 텍스트 하나로 늘어나는 파일 크기가 100KB 이하다. Acrobat Reader·Edge·Chrome에서 같은 모습으로 보이고, 하이라이트 아래 글자가 보이고, 텍스트를 복사하면 원문이 나온다(사람 확인). |
| M0-5 | 화면 일치 | 같은 모델을 오버레이로 그린 화면과 내보낸 PDF를 렌더링한 화면의 객체 위치 차이가 1px 이하다. 회전 0/90/180/270 페이지에서 모두 확인한다. |
| M0-6 | 보고 | `docs/M0_REPORT.md`에 측정값, 틀린 가정, 스택 변경 제안을 적는다. DECISIONS와 CLAUDE.md의 명령 절을 실제에 맞게 고친다. |

### M1. 뷰어

- PDF 여러 개와 이미지를 추가하면 한 문서로 이어져 보인다.
- 썸네일 패널, 연속 스크롤, 줌, 쪽 이동이 6.2절대로 동작한다.
- 300쪽 fixture에서 보이는 페이지만 렌더링되고 스크롤이 끊기지 않는다.
- 암호 PDF는 비밀번호를 넣으면 열리고, 틀리면 다시 묻는다.
- 읽을 수 없는 파일은 오류를 보여 주고 앱은 계속 동작한다.
- 좌표 변환 단위 테스트와 브라우저 모드 스모크 테스트가 있다.

### M2. 페이지 정리와 병합 저장

- 순서 변경, 여러 장 선택, 삭제, 회전, Undo/Redo가 6.3절대로 동작한다.
- 이미지 페이지의 맞춤 방식을 바꿀 수 있다.
- 다른 이름으로 저장한 PDF의 쪽수, 순서, 회전, 크기가 모델과 일치한다(코어 테스트).
- 저장 뒤에도 원본 파일은 그대로다(해시 비교).
- 소스와 같은 경로로 저장하려 하면 거부한다.
- 결과가 뷰어 세 종에서 열린다(사람 확인).

### M2.5. 다국어 UI

- UI 문자열이 한국어, 영어, 일본어 사전에 모여 있고, 세 사전의 키가 같다(단위 테스트, 타입 검사).
- 시스템 언어에 맞는 언어로 시작하고, 지원하지 않는 언어면 영어로 시작한다(E2E).
- 언어를 바꾸면 화면의 문구, 창 제목, 저장 기본 이름이 바뀌고 문서는 그대로다. 고른 언어는 다시 열어도 유지된다(E2E, 사람 확인).
- 영어 README가 있다.

### M3. 객체 공통 조작, 도형, 하이라이트

- 선택, 이동, 크기 조절, 삭제, 속성 변경, Undo/Redo가 6.4절대로 동작한다.
- 하이라이트, 사각형, 타원, 직선, 화살표를 만들 수 있다.
- 저장하면 표준 주석으로 기록된다. Acrobat Reader와 Edge에서 주석으로 인식되어 옮기거나 지울 수 있다(사람 확인).
- 화면 일치 테스트가 회전 페이지를 포함해 통과한다.
- 하이라이트 아래 글자가 보인다.

### M4. 서명

- 보관함의 등록, 목록, 이름 변경, 삭제가 동작하고 앱을 다시 켜도 유지된다.
- 배치, 비율 유지 크기 조절, 이동, 삭제가 동작한다.
- 저장하면 페이지 콘텐츠로 구워진다. 다른 뷰어에서 주석으로 선택되지 않고 투명 배경이 유지된다.
- 같은 서명을 여러 번 배치해도 이미지 데이터는 출력에 한 번만 들어간다(코어 테스트).

### M5. 텍스트

- 입력, 줄바꿈, 확정, 취소, 다시 편집이 6.7절대로 동작한다. 한글 조합이 정상이다.
- 글자 크기와 색을 바꿀 수 있다.
- 저장하면 FreeText 주석과 서브셋 폰트로 기록된다. 뷰어 세 종에서 같은 모습이고 M0-4의 파일 크기 기준을 지킨다.
- 폰트에 없는 글자는 저장할 때 알려 준다.
- 화면 일치 테스트가 텍스트를 포함해 통과한다.

### M6. 다시 열기와 평탄화 내보내기

- 이 앱으로 저장한 PDF를 추가하면 하이라이트, 도형, 텍스트가 편집 가능한 객체로 돌아온다.
- 다른 프로그램이 위치를 바꾼 주석은 객체로 되살리지 않고 그대로 둔다.
- 저장, 다시 열기, 저장을 거친 결과의 객체가 처음과 같다(왕복 테스트).
- 평탄화하여 내보내기가 동작하고, 결과에는 이 앱이 만든 주석이 남지 않는다.

### M7. 마감과 공개 준비

- 창 크기와 최근 설정이 유지된다. 오류 메시지와 단축키 도움말을 정리한다.
- 11장의 공개 준비 항목을 갖춘다.
- 전체 사람 확인 점검표가 통과한다.

## 11. 공개 배포 준비

- 지금은 설치 프로그램 없이 exe 하나로 실행한다. WebView2는 Windows 11에 들어 있다.
- 저장소는 처음부터 공개해도 되는 상태로 유지한다. 개인 파일과 비밀 값을 넣지 않고 의존성의 라이선스를 확인한다.
- 공개 전에 상표 검색(KIPRIS)으로 "HumblePDF"를 확인한다(DECISIONS D34).
- 공개 전에 할 일(M7): 라이선스 파일, 서드파티 고지(PDF.js Apache-2.0, Pretendard OFL 1.1 등), README, CI(fmt, clippy, 테스트, 빌드), 릴리스 워크플로(포터블 exe).
- 후순위: 설치 프로그램, 코드 서명(서명이 없는 exe는 Windows SmartScreen 경고가 뜬다), 자동 업데이트.
