## 만든 것

- **일본어 폰트** (D32)
  - Pretendard JP Regular를 받아 JIS X 0208 전체(가나, 기호, 제1·제2수준 한자)와 전각 영숫자만 남겼다.
  - 크기는 5.46MB에서 2.01MB로 줄었다. 재생성 명령은 `npm run fonts`다.
- **core**
  - `FontSet`: 글자마다 Pretendard → Pretendard JP 순으로 폰트를 고른다.
  - 한 줄을 폰트별 조각으로 나눠 그린다(조각마다 `Tf`, `Tj`가 `/W` 폭만큼 진행).
  - 쓰인 폰트만 각각 서브셋으로 넣는다.
- **프런트엔드** (D33)
  - 두 폰트를 웹 폰트로 등록한다.
  - 텍스트 도구(T)와 제자리 입력 상자: 같은 폰트, 크기, 줄 간격, 회전으로 그린다.
  - Enter, Ctrl+Enter, 바깥 클릭, Esc, 더블클릭으로 다시 편집. 모두 지우면 객체를 지운다.
  - 글자 크기와 색, 이동, 방향키, 삭제, Undo
- **문자열:** ko, en, ja
- **사람 확인 샘플:** `npm run sample`이 `out/m5_sample.pdf`(4쪽)를 만든다. 일부러 넣은 없는 글자 하나에 대해 경고가 나온다.

## 계획과 달라진 점, 발견한 문제

1. **한자 범위를 "제1+제2수준 전체"로 바꿨다.** 계획은 "제1수준 + 상용한자"였다. 그런데 상용한자 목록을 오프라인에서 구할 수 없어서 여쭈었고, 제1+제2수준을 고르셨다. 제1수준만이면 0.88MB이지만 2010년 추가 상용한자 약 70자가 빠진다.
2. **원본에 없는 글자가 있다.**
   - 반각 가타카나(ｱ 등)와 일부 수학·괘선 기호(∀, ─ 등) 171자는 원본 Pretendard JP에 없다.
   - 이 글자들은 저장할 때 빈칸으로 처리하고 알린다. 화면에서는 시스템 폰트로 보일 수 있다.
3. **Pretendard에도 가나가 있다.** 규칙상 가나는 Pretendard, 한자는 Pretendard JP로 그려진다. 같은 계열이라 모양 차이는 눈에 띄지 않는다. 계획의 "일본어만 쓴 문서에는 Pretendard가 들어가지 않는다"는 검사는 "한자만 쓴 문서에는 Pretendard JP만 들어간다"로 바꿨다.
4. **FreeText `/DA`는 그대로 `/Helv`다.** 계획에는 "첫 폰트"라고 적었다. 하지만 모양은 `/AP`가 정하고, M0에서 뷰어 세 종으로 확인한 방식이라 바꾸지 않았다.
5. **폰트 배정 규칙의 프런트엔드 단위 테스트는 없다.** 화면은 브라우저의 CSS 글꼴 대체로 규칙을 따르고, Node에는 브라우저 글꼴이 없어 단위 테스트를 만들 수 없다. 대신 화면 일치 E2E가 혼합 텍스트로 확인한다.

6. **텍스트가 페이지 밖으로 넘쳤다(사람 확인에서 발견).**
   - 샘플: `m5_sample.pdf`의 180°·270° 페이지에서 텍스트가 잘렸다. 샘플 스크립트가 위치를 회전과 상관없이 PDF 좌표로 줘서, 화면 기준 오른쪽 가장자리 근처에서 시작했기 때문이다. 화면 기준 위치(표시된 페이지의 왼쪽 위에서 잰 값)로 고쳤다.
   - 앱: 페이지 끝 근처에서 입력하거나 글자 크기를 키우면 텍스트가 넘칠 수 있었다. 확정할 때와 속성을 바꿀 때 페이지 안으로 밀어 넣는다(`keepInside`, SPEC 6.4 "페이지 밖으로 나가지 않는다"). 단위 테스트와 E2E(`text typed near the page edge is kept on the page`, 0°·180° 페이지)를 더했다.

## 남은 위험

- **실제 IME:** CDP 흉내는 Windows의 한글·일본어 입력기를 완전히 재현하지 못한다. 사람 확인이 최종이다.
- **폰트가 없는 글자의 화면 표시:** 두 폰트에 없는 글자는 화면에는 시스템 폰트로 보이지만 저장하면 빈칸이다. 저장할 때 알림으로 알린다.
- **캔버스 측정과 합자:** 선택 상자의 폭은 캔버스로 재므로, 합자가 있는 글꼴 조합에서는 실제 폭과 약간 다를 수 있다. 저장 결과에는 영향이 없다.

## 사람 확인 점검표

`npm.cmd run tauri dev`로 앱을 연다.

1. **입력:** 텍스트 도구(T)로 페이지를 클릭하고 입력한다.
   - Windows 한글 입력기로 한글이 정상 조합되는가
   - 일본어 입력기(설치되어 있다면)로 가나와 한자 변환이 되는가
   - Enter로 줄이 바뀌는가, Ctrl+Enter와 바깥 클릭으로 확정되는가, Esc로 취소되는가
   - 확정 전후 글자 위치가 그대로인가
2. **다시 편집:** 텍스트를 더블클릭해 고친다. 모두 지우고 확정하면 사라지는가.
3. **속성과 편집:** 글자 크기와 색을 바꾼다. 옮기기, 방향키, Delete, Ctrl+Z가 되는가.
4. **회전된 페이지:** 회전된 페이지에서도 똑바로 입력되는가.
5. **다른 뷰어:** `npm.cmd run sample`이 만든 `out\m5_sample.pdf`와 앱에서 저장한 파일을 Acrobat Reader, Edge, Chrome에서 연다.
   - 세 뷰어의 모습이 같은가
   - 글자를 복사하면 원문(일본어 포함)이 나오는가
   - Acrobat Reader와 Edge에서 텍스트 상자 주석으로 옮기고 지울 수 있는가
