## 만든 것

- **사전** (`src/i18n/`, D27)
  - `ko.ts`가 키의 원본이고, `en.ts`와 `ja.ts`가 같은 모양을 채운다. 옛 `src/strings/ko.ts`는 여기로 옮겼다.
  - 영어는 쪽수에 따라 단수·복수를 바꾼다("Moving 1 page", "Moving 3 pages").
  - 저장 기본 이름의 접미사: `_편집`, `_edited`, `_編集`
- **언어 저장소:** 컴포넌트는 `useStrings()`, 컴포넌트 밖(저장, 알림, 백엔드)은 `strings()`를 쓴다. 언어를 바꾸면 화면이 바로 바뀌고 문서, 선택, Undo 이력은 그대로다.
- **처음 언어:** 저장해 둔 선택 → 시스템 언어 목록에서 처음 맞는 언어 → 영어
- **툴바 언어 선택:** 오른쪽 끝. 언어 이름은 각 언어로 적는다(한국어, English, 日本語).
- **창 제목과 `lang` 속성**
  - 언어를 따라 바뀐다. Tauri에서는 `setTitle`을 쓰고, 권한 `core:window:allow-set-title`을 추가했다.
  - 언어를 정하기 전에 잠깐 보이는 기본 제목은 `PDF Editor`로 바꿨다.
- **E2E:** 기존 테스트는 한국어 문구를 읽으므로 Playwright 기본 locale을 `ko-KR`로 고정했다.
- **README.md(영어):** 소개, 기능, 스택, 빌드·테스트 명령, 구조, 번역 기여 방법

## 계획과 달라진 점

1. **사전 위치를 `src/strings/`에서 `src/i18n/`으로 옮겼다.** 언어 저장소와 함께 두기 위해서다. CLAUDE.md의 규칙도 고쳤다.
2. **기본 창 제목을 영어로 바꿨다.** `tauri.conf.json`과 `index.html`의 제목은 언어를 정하기 전에 잠깐 보인다. 공개용 기본값으로 영어가 맞다.
3. **한국어 오류 사전을 정확한 키 목록으로 바꿨다.** 예전에는 `Record<string, string>`이었다. 이제 영어·일본어 사전에서 오류 키가 빠지면 타입 검사가 실패한다. 모르는 코드는 전처럼 일반 오류 문구로 보인다.

## 남은 위험

- **일본어 번역은 원어민 검토 전이다.** 공개 전에 검토를 받기를 권한다.
- **일본어 텍스트 객체:** 번들 폰트에 일본어 글리프가 거의 없다. M5 계획 때 폰트를 정한다(DECISIONS 미정 표).
- **WebView2의 언어 목록:** `navigator.languages`가 Windows 표시 언어를 따르는지는 Tauri에서 사람이 확인해야 한다. 브라우저 모드에서는 E2E로 확인했다.
- **언어 선택은 WebView 저장소(`localStorage`)에 남는다.** 앱 데이터 폴더를 지우면 시스템 언어로 돌아간다.

## 사람 확인 점검표

`npm.cmd run tauri dev`로 앱을 연다.

1. **처음 언어:** 처음 열면 Windows 표시 언어(한국어)로 보이는가
2. **바꾸기:** 툴바 오른쪽 끝의 언어 선택에서 English, 日本語로 바꾼다.
   - 툴바 툴팁, 빈 화면 안내, 썸네일 쪽 번호, 오른쪽 클릭 메뉴가 바뀌는가
   - 창 제목 표시줄이 `PDF Editor`, `PDF エディター`로 바뀌는가
3. **문서 유지:** 파일을 연 채 언어를 바꿔도 페이지와 Undo가 그대로인가
4. **저장 대화상자**
   - 파일 열기 대화상자의 형식 이름이 언어를 따르는가
   - 저장 기본 이름이 `…_edited.pdf`, `…_編集.pdf`인가
5. **유지:** 앱을 닫았다가 다시 열면 마지막에 고른 언어로 시작하는가
6. **일본어 화면:** 잘리거나 겹친 문구가 없는가
