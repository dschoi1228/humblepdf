## 만든 것

- **편집 오버레이** (`src/components/ObjectLayer.tsx`, D28)
  - 객체마다 SVG 하나다. 그리는 코드는 M0-5에서 검증한 `objectSvg`를 그대로 쓴다.
  - 하이라이트는 SVG 요소에 곱하기 블렌드를 걸어 아래 글자와 섞인다.
  - 선택 도구
    - 누르면 위에 있는 객체부터 고른다.
    - 끌면 옮기고, 핸들로 크기를 바꾼다. 선은 끝점 2개, 나머지는 핸들 8개다.
    - 빈 곳을 누르면 선택을 푼다.
  - 그리기 도구: 끌어서 만들고, 끄는 동안 임시 모양을 보여 준다. Esc로 취소한다.
  - 객체와 핸들은 페이지 상자 밖으로 나가지 않는다.
  - 썸네일에도 같은 SVG로 객체를 보여 준다.
- **기하** (`src/editor/geometry.ts`, 사용자 공간의 순수 함수)
  - 맞힘 판정, 이동, 크기 조절(최소 4pt), 45° 고정, 클릭으로 만들 때의 기본 크기(화면 기준 120×80pt, 선 120pt)
  - 회전된 페이지에서도 방향키와 클릭 크기는 화면 방향을 따른다. 좌표 모듈에 `deltaToUser`, `screenAxes`, `rectToScreen`을 더했다.
- **편집 저장소와 명령** (`src/editor/editorStore.ts`, `src/app/objectActions.ts`)
  - 현재 도구, 선택, 도구별 최근 속성
  - 객체 추가·변경·삭제는 `apply` 한 번, 곧 Undo 한 칸이다.
- **편집 막대** (`src/components/EditBar.tsx`, D29)
  - 툴바 아래 둘째 줄. 도구 6개, 선 색, 두께, 채움, 불투명도, 객체 삭제 버튼이 있다.
  - 도형이 선과 채움이 둘 다 없는 상태는 고를 수 없다.
- **단축키**
  - V, H, R, O, L, A로 도구를 고른다.
  - Esc: 끄는 중이면 취소, 그리기 도구면 선택 도구로, 선택 도구면 선택 해제
  - 방향키 1pt, Shift+방향키 10pt
  - Delete는 선택한 객체를 먼저 지우고, 없으면 페이지를 지운다.
- **core 검증:** 저장할 때 객체 값을 확인한다. 겹치는 ID, 범위 밖 값, 보이지 않는 도형 등은 `InvalidModel`이다. 선 두께 범위는 모양 수치 파일에 두어 프런트엔드와 같은지 테스트한다.
- **문자열:** 편집 도구와 색 이름을 한국어, 영어, 일본어로 넣었다.
- **사람 확인 샘플:** `npm run sample`이 `out/m3_sample.pdf`(5쪽)를 만든다.

## 계획과 달라진 점, 발견한 문제

1. **화면 일치 측정을 캔버스를 숨긴 화면으로 했다.**
   - A4처럼 크기가 정수 픽셀이 아닌 페이지에서 문제가 생겼다. 100% 배율에서 595px 캔버스가 595.28px 칸에 아주 조금 늘어나 그려진다. 그래서 페이지의 모든 테두리가 흐려지고, "바뀐 영역"이 페이지 전체로 잡혔다.
   - 그래서 오버레이 비교에는 캔버스를 숨긴 스크린숏(흰 바탕 위 객체)을 쓴다. 글자가 보이는지 확인할 때는 캔버스가 보이는 스크린숏을 따로 쓴다.
   - 같은 이유로 스크린숏 바깥 2px은 무시한다. 소수점 위치의 페이지 요소는 회색 배경이 가장자리 픽셀에 섞인다. 객체는 그곳에 두지 않는다.
   - 화면에서 이 흐림은 눈으로 구분하기 어렵다. 뷰어 품질 문제로 기록해 둔다.
2. **객체 ID는 문서 안에서 유일해야 한다.** core가 겹치는 ID를 거부하게 하자, M0-5 화면 일치 테스트가 페이지마다 같은 ID를 써서 실패했다. 테스트가 페이지마다 다른 ID를 쓰도록 고쳤다. 편집기는 UUID를 쓴다.
3. **파일 추가도 Undo 한 칸이라**(M2), E2E의 Undo 칸 수는 파일을 연 뒤의 값을 기준으로 센다.
4. **방향키 기준:** 회전된 페이지에서 →키는 화면 오른쪽으로 움직인다. 90° 시계 방향으로 보이는 페이지에서는 사용자 공간의 +y 방향이다. 단위 테스트에서 처음 기대값을 거꾸로 적어 고쳤다(코드 문제는 아니었다).
5. **`IconButton`을 따로 뺐다.** 툴바와 편집 막대가 함께 쓴다(`src/components/IconButton.tsx`).

## 남은 위험

- **객체가 많을 때의 성능은 재지 않았다.** 페이지마다 객체 수백 개면 SVG가 많아진다. 보이는 페이지만 그리므로 범위는 작다.
- **속성 선택 칸에 포커스가 남는다.** 두께나 불투명도를 고른 직후에는 포커스가 선택 칸에 있다. 그래서 Delete나 방향키가 객체가 아니라 선택 칸에 간다. 웹 표준 동작이라 그대로 두었다. 불편하면 고친다.
- **다시 열기는 M6이다.** 지금은 저장한 PDF를 다시 열면 주석이 PDF.js 캔버스에 그려질 뿐, 편집할 수 있는 객체가 아니다.

## 사람 확인 점검표

`npm.cmd run tauri dev`로 앱을 연다.

1. **그리기:** `korean_embedded.pdf`와 `rotated.pdf`를 추가한다.
   - 편집 막대의 도구 버튼과 단축키(H, R, O, L, A)로 다섯 가지를 그려 본다.
   - 회전된 페이지에서도 끄는 대로 그려지는가
   - 하이라이트를 그린 뒤에는 도구가 그대로이고, 사각형을 그린 뒤에는 선택 도구로 돌아오는가
   - Shift를 누르고 직선을 그리면 45° 단위로 고정되는가
2. **선택과 편집**
   - 객체를 클릭해 선택하고, 끌어 옮기고, 핸들로 크기를 바꾼다.
   - 방향키와 Shift+방향키로 옮긴다.
   - 페이지 밖으로 끌어도 페이지 안에 남는가
   - 감각이 자연스러운가
3. **속성:** 선 색, 두께, 채움, 불투명도를 바꾼다. 바로 반영되는가. Ctrl+Z로 하나씩 돌아가는가.
4. **삭제와 Esc**
   - Delete와 편집 막대의 휴지통으로 지울 수 있는가
   - 객체를 선택하지 않았을 때 Delete는 예전처럼 페이지를 지우는가
   - Esc를 누르면 도구 → 선택 해제 순으로 동작하는가
5. **하이라이트:** 글자 위에 칠해도 글자가 잘 보이는가.
6. **썸네일:** 객체를 그리면 썸네일에도 보이는가.
7. **다른 뷰어:** `npm.cmd run sample`이 만든 `out\m3_sample.pdf`와 앱에서 저장한 파일을 Acrobat Reader, Edge, Chrome에서 연다.
   - 세 뷰어에서 객체 모양과 위치가 같은가(명령이 출력한 목록 참고)
   - Acrobat Reader와 Edge에서 각 객체가 주석으로 선택되고, 옮기고, 지울 수 있는가
   - 하이라이트 아래 글자가 읽히는가
