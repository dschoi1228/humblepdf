## 만든 것

- **찾기 막대** (`FindBar.tsx`)
  - Ctrl+F나 툴바의 돋보기 버튼으로 보기 오른쪽 위에 연다.
  - 검색어 칸, "현재/전체" 결과 수, 이전·다음·닫기 버튼이 있다.
  - 한 줄 안에서 선택한 본문 텍스트가 있으면 검색어로 채운다.
- **찾기 규칙** (`src/search/match.ts`): 대소문자를 무시하고 NFKC로 정규화한다. 공백 덩이는 공백·줄바꿈과 맞는다. 한 쪽 안에서만 찾는다.
- **검색 상태** (`searchStore.ts`)
  - 취소할 수 있는 비동기 검색이다. 쪽 글자는 원본 쪽 단위로 캐시한다.
  - 쪽을 바꾸면(추가, 삭제, 순서) 다시 찾는다.
- **표시** (`SearchLayer.tsx`)
  - 캔버스와 텍스트 레이어 사이에 노란 상자, 현재 결과는 주황 상자로 그린다.
  - 저장·인쇄·썸네일에는 없다.
- **단축키:** Enter·F3 다음, Shift+Enter·Shift+F3 이전, Esc 닫기. 단축키 도움말에 세 언어로 더했다.
- **쪽 맞춤:** 모든 쪽이 통째로 들어오는 배율로 바꿨다.
- **글자 위치 보정** (`glyphLayout.ts`, 사람 확인 뒤 추가): 연산자 목록에서 글자마다 실제 위치를 구해 span 폭과 상자의 가로 범위를 맞춘다. 검색 상자와 M13 글자 하이라이트에 함께 쓴다.

core, PDF 출력, 의존성은 바뀌지 않았다.

## 계획과 달라진 점

1. **쪽 맞춤을 "모든 쪽이 들어오는 배율"로 바꿨다.**
   - 계획은 "현재 쪽이 바뀔 때마다 그 쪽에 다시 맞춤"이었다. 그렇게 하면 세로·가로가 섞인 문서를 스크롤하는 동안 배율이 계속 바뀌어 화면이 출렁인다.
   - 너비 맞춤이 이미 가장 넓은 쪽을 기준으로 하므로, 같은 방식으로 맞췄다.
   - 가로 쪽은 조금 작게 보인다.
2. **사람 확인에서 상자 위치가 어긋나 글자 위치 보정을 더했다.**
   - 한글 뒤의 숫자 "0"을 찾으면 상자가 글자 옆에 그려졌다(300%에서 두 글자 옆).
   - 원인: 텍스트 레이어가 브라우저 대체 글꼴로 글자를 놓는다. 그런데 pdf.js가 폭을 잰 캔버스와 화면 span이 서로 다른 대체 글꼴을 골랐다.
   - 처음 테스트는 줄 시작 위치만 확인해서 이 문제를 놓쳤다.
   - 연산자 목록으로 실제 글자 위치를 구해 맞췄다(D49). 브라우저가 그리는 파란 선택 영역은 여전히 대체 글꼴 기준이라 조금 다를 수 있다. 하지만 하이라이트(M13)와 검색 상자는 글자에 맞는다.
3. **"쪽 맞춤 배율" Vitest는 따로 두지 않았다.** 계산이 한 줄(각 쪽 배율의 최솟값)이라 E2E 한 개로 확인한다.

## 남은 위험

- **WebView2의 Ctrl+F:** 브라우저 모드에서는 앱이 키를 받아 기본 찾기를 막는다. 실제 exe에서 WebView2 자체 찾기가 먼저 뜨는지는 사람 확인이 필요하다.
- **여러 단·표:** 줄을 넘는 구절은 내용 순서로 찾으므로 화면 순서와 다를 수 있다(M12와 같음).
- **아주 많은 글자의 쪽:** pdf.js가 span을 10만 개에서 멈추면, 그 뒤 결과는 수에는 들어가지만 상자는 그리지 않는다.
- **글자 위치 보정이 안 되는 경우:** 글리프와 텍스트를 맞추지 못한 항목, 세로쓰기, 쪽 안에서 기울어진 글자는 브라우저 배치를 쓴다. 이때는 줄 안의 상자가 조금 어긋날 수 있다.
- **스캔 PDF:** 글자 정보가 없으면 찾을 수 없다(OCR은 범위 밖).

## 사람 확인 점검표

2026-11-26 사용자가 아래 항목을 확인했다(통과). 처음 확인에서 줄 가운데 결과(한글 뒤 숫자)의 상자가 어긋나 글자 위치 보정을 더했고, 다시 확인해 "대체로 맞다"는 결과를 받았다.

`target\release\HumblePDF.exe`(이 마일스톤으로 다시 빌드)로 확인한다.

1. **Ctrl+F:** PDF를 열고 Ctrl+F를 누른다. 앱의 찾기 막대(오른쪽 위)가 열리고, Edge 식 기본 찾기 창은 뜨지 않는가.
2. **찾기와 이동:** `tests\fixtures\text_select.pdf`와 평소 쓰는 PDF에서 한글·영문 단어를 찾는다.
   - 결과 수가 맞고, 글자 위에 노란·주황 상자가 보이는가.
   - Enter·F3로 다음, Shift+Enter로 이전 결과로 가며 다른 쪽으로 넘어가는가.
3. **확대·회전:** 확대한 상태와 회전한 쪽에서도 상자가 글자 위에 있는가.
4. **선택에서 찾기:** 본문을 선택한 뒤 Ctrl+F를 누르면 그 글자로 찾는가. Esc로 닫으면 표시가 사라지는가.
5. **쪽 맞춤:** 세로·가로 쪽이 섞인 문서에서 "쪽 맞춤"을 누르면 모든 쪽이 통째로 보이는가.
