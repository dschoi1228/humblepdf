## 만든 것

- **텍스트 레이어:** PDF 쪽마다 pdf.js `TextLayer`를 캔버스와 객체 레이어 사이에 둔다(`src/viewer/textLayer.ts`). 글자는 투명하고 선택 색만 보인다. 캔버스를 처음 그린 뒤에 만들고, 확대·축소는 CSS 배율만 바꾼다.
- **끌어 선택하기:** 앱이 선택 범위를 직접 만든다. 줄 끝 너머는 그 줄의 끝, 줄 사이는 다음 줄의 시작으로 맞춘다. 보기 가장자리에서 자동으로 스크롤하고 다음 쪽까지 이어서 선택한다. 쪽과 쪽 사이는 줄을 바꾼다.
- **객체 우선:** 선택 도구에서 포인터가 객체나 손잡이 위에 없을 때만 텍스트가 포인터를 받는다.
- **복사와 Esc:** Ctrl+C는 텍스트 선택이 있으면 텍스트를, 아니면 객체를 복사한다. Esc는 텍스트 선택을 푼다. 단축키 도움말의 "복사" 설명을 세 언어로 바꿨다.
- **합성 fixture:** `tests/fixtures/text_select.pdf`. 영문(Helvetica), 한글(Pretendard 서브셋), 일본어(Pretendard JP 서브셋) 세 줄. 둘째 쪽은 /Rotate 90.

core, PDF 출력, 의존성은 바뀌지 않았다.

## 계획과 달라진 점

1. **끌어 선택하기를 브라우저에 맡기지 않았다.** 처음에는 pdf.js 뷰어처럼 브라우저 선택을 쓰려 했다. 그런데 Edge 158에서 줄 끝을 지나 놓으면 그 줄이 빠지고, 여백에서 시작하면 아무것도 선택되지 않았다. pdf.js 뷰어의 end-of-content 방식으로도 같았다. 그래서 한 번 눌러 끄는 동작만 앱이 처리한다. 더블클릭·세 번 클릭과 Shift+클릭은 브라우저 동작 그대로다.
2. **쪽을 넘는 선택과 자동 스크롤을 더했다.** 직접 처리하면서 브라우저가 해 주던 자동 스크롤을 다시 만들어야 했다.

## 남은 위험

- 글자 정보가 없는 스캔 PDF와 이미지 쪽은 선택할 것이 없다(OCR은 범위 밖).
- 글자를 이상한 순서로 쓴 PDF(여러 단, 표)는 "다음 줄"을 내용 순서로 정하므로 선택 범위가 화면 순서와 다를 수 있다. 브라우저와 pdf.js 뷰어도 같은 한계가 있다.
- 기울어진 글자(회전한 텍스트)는 줄 판정이 정확하지 않을 수 있다. 쪽 회전(90° 단위)은 맞춘다.
- 오른쪽 클릭 메뉴는 WebView 기본 메뉴의 "복사"다. 앱 자체 메뉴는 아니다.

## 사람 확인 점검표

`target\release\HumblePDF.exe`(이 마일스톤으로 다시 빌드)로 확인한다.

1. `tests\fixtures\text_select.pdf`와 평소 쓰는 PDF 몇 개를 연다.
2. 선택 도구로 본문을 끌어 선택하고 Ctrl+C → 메모장에 붙여 넣는다. 같은 글자인가.
3. 더블클릭은 단어, 세 번 클릭은 줄을 선택하는가.
4. 줄 끝 너머나 왼쪽 여백에서 끌어도 줄 단위로 자연스럽게 선택되는가. 아래로 끌어 보기 끝에 닿으면 스크롤되며 다음 쪽까지 선택되는가.
5. 확대한 상태, 회전한 쪽에서도 선택 영역이 글자와 맞는가.
6. 하이라이트·도형 위를 누르면 객체가 선택되고, 그 객체를 Ctrl+C·Ctrl+V로 복사할 수 있는가.
